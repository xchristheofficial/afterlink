# AfterLink · a product of Kodra

See the [30-upgrade browser batch](docs/30-browser-upgrades.md) for new notification, saved-library, reel, chat, group, profile and call controls and how they were tested.

Reference-led account access page. The left panel is noninteractive artwork from the supplied design, not a feed or a source of database records. The right panel is a responsive HTML form. The application starts with no accounts or content. See [PRODUCT.md](PRODUCT.md) for the product proposal.

## Run

Node 22.13 or newer (built-in SQLite), `npm ci`, then `npm start`. The app serves the page and API from one origin on port 3000. Run `npm test` for the isolated authentication, recovery, and social settings tests; it never touches the live database.

**Database-free performance check:** `npm run test:speed` serves only public files, compares Brotli/gzip with uncompressed transfers, checks which scripts each page loads, and simulates slow unread-count requests. It never starts the application or opens SQLite. Private API responses, live event streams and signed-in HTML are not routed through the public asset compressor.


For browser checks, install Chromium with `npx playwright install --with-deps chromium`, then run `npm run test:ui`. The script starts a separate service with a temporary database, exercises the actual page, and removes the database afterward.

## Accounts

Select **Sign up** and enter a full name, unique username (3–30 letters, numbers, or underscores), email and password of at least 12 characters. Both forms share one decorative image. Sign in with email and password. Existing accounts remain usable without a username. Phone is an optional contact field, not SMS verification. Email/password accounts do not claim the address has been verified. After login the home feed shows real persisted activity.

Accounts and revocable, seven-day sessions are stored in `data/afterlink.sqlite`. Passwords use salted scrypt hashes; session tokens are random, hashed in storage and held in HTTP-only cookies in the browser. Never commit or serve the data directory. Run behind HTTPS with `NODE_ENV=production` to require secure cookies. Use a persistent volume and backups for the database in a deployed single-instance service; a workspace preview is not production hosting.

## Keeping data across deployments

Submitted accounts, posts, media, relationships, settings, and conversations are saved in the server’s SQLite database, not just in the browser. Logging out does not delete them. A process restart or a new release must reopen **the same database file**. Production requires an absolute `DB_FILE` and an existing parent directory; a path by itself does not make a disk persistent.

- **Free plan with no disk (Postgres/Supabase):** set `DATABASE_URL` to a Postgres connection string and the service keeps the durable copy there, so a redeploy, restart or spin-down restores the same accounts. SQLite stays the live engine on the container's own filesystem; a verified snapshot is restored at startup and replicated back a few seconds after each write, on an interval, and on shutdown. See [Postgres-backed persistence](docs/supabase-persistence.md) for the exact Render and Supabase steps. This path is for a single instance: a second instance that finds a newer stored snapshot stops replicating instead of overwriting it.
- **Existing Render service:** before making any change that triggers a redeploy, pause writes and take a SQLite-consistent backup of the current database to secure storage outside the service. For example, with the SQLite CLI use `sqlite3 /actual/path/afterlink.sqlite ".backup '/private/path/afterlink-backup.sqlite'"`, then export the backup. Do not copy only a live `.sqlite` file while it has WAL writes. Attach a persistent disk mounted at `/var/data`, restore the backup there as `afterlink.sqlite` **before accepting traffic**, and set `DB_FILE=/var/data/afterlink.sqlite`. If already using a persistent disk, keep the current mount and filename. Do not replace an existing database with an empty one.
- **New Render service:** `render.yaml` describes a single Node service with a 1 GB persistent disk. This requires a paid disk-capable plan. Adding the file to Git does not attach a disk to an existing service. On other hosts, mount a persistent volume and set `DB_FILE` equivalently.
- **Backups:** keep private, regularly tested backups off-volume and back up the authenticator encryption key separately. Never serve or commit a database or backup. Monitor disk space, especially when users upload media.
- **Release checks:** Run `npm run --silent storage:health` in the service shell with its existing absolute `DB_FILE`. Run `npm run test:restore` locally for the disposable restore drill. Follow the [SQLite release and rollback checklist](docs/sqlite-release.md) before deploying schema changes.

`tests/persistence.test.mjs` writes data through the API, kills the server, starts a new process on the same database and signs in again to verify the records survived.

## Home feed

Signing in opens `/home`, the bookmarkable, session-protected Home Feed. Opening `/home` while signed out returns you to sign-in. The responsive feed opens with a post composer, people search, follow/unfollow, follower counts and saved posts. The latest 50 posts by the viewer or accounts they follow are shown newest first. All records and counts start empty. Stories, the inbox, and the activity center use real member data.

The first account in this SQLite database (lowest user ID) is bound once to the **RADAR** public display name and developer badge. This changes neither its credentials nor its username, and grants no permissions. Other accounts use their own profile details; public directory and feed responses exclude emails and phone numbers. Keep the database on persistent storage to retain this association. Site transitions are opt-in via the browser’s no-reduced-motion preference.

## Create Post

Open `/create` from the Home Feed or your empty profile. Write up to 500 characters, choose Everyone (signed-in members) or Followers, attach up to ten photos/GIFs or one MP4/WebM video, add a two-answer poll, a feeling, or a typed place. Uploads are limited to 8 MB per post and 128 MB of published media per member. Media, votes, and one private saved draft per member use the same persistent SQLite database as posts. **Drafts** lets you explicitly save, reopen, replace, or delete your draft. Following status and account privacy apply to the feed, shared profiles, saved posts, votes and direct media requests. Nothing is posted until Publish succeeds.

**Browsing posts:** Long captions in the feed, on profiles, on posts and on reels have **Read more / Show less** controls. In a multi-attachment post, focus the gallery and use Left/Right to browse or Home/End for the first/last attachment. Explore keeps the selected People, Posts or Reels filter when you open a result and go back, reload, or refine your search. Run `npm run test:browsing-ui` with Playwright Chromium for a database-free rehearsal.

**Back to the feed:** Open a post with **Open post & comments**, then use Back. If the browser has to rebuild the home feed, it returns focus to the same post link at the previous reading position and reopens its expanded caption. If the post is gone, it tries an adjacent post still visible to the same member. No caption text or media is saved for this.

**Private list filters:** Notifications can limit any category to people you follow. Open a saved collection to filter its posts by caption and author keywords in any order. In Settings → Privacy & Safety, filter blocked and muted accounts by display name or restriction type. Collection and restriction searches stay in the page; their terms are not sent to the server or added to the URL.

## Profiles

Open **Profile** from the home sidebar, or select a name in a post or Explore People. `/profile` shows your account; `/profile/<id>` is a stable link you can share with other members. Bios and display-name edits are persisted for the signed-in owner. RADAR’s public founder name and badge cannot be changed through this form. The profile grid lists the latest 50 posts while the count covers all posts. Saved posts are only available to their owner. The Reels tab shows video posts. Tagged has an empty state until tagging is implemented. Motion enhancements respect reduced-motion preferences.

### Edit Profile

**Share Profile** copies the profile’s numeric link without query parameters or fragments. On supported devices you can also use **Share via device**. If clipboard access is denied, the link is selected for manual copying. Sharing does not broaden the account’s audience.

**Settings → Account & Security** explains group admin succession and last-member closure before asking for the final account-deletion confirmation. You can review your groups and hand off the admin role first. Password and deletion-confirmation mistakes are explained at the field to correct.

**Settings → Privacy & Safety → Download settings** saves a dated JSON snapshot of the current account’s privacy, appearance/playback, and notification preferences. It rechecks the signed-in member before download and excludes contact details, restrictions, sign-in information, and message content. This is a preferences export, not a full account backup.

`/profile/edit` edits the signed-in account. New photos start centered. Use **Photo framing** to choose left/center/right for a wide photo or top/center/bottom for a tall one. **Undo photo change** restores the current avatar without clearing other edits. Only the chosen 256×256 JPEG is submitted on Save. Switching a private account to public requires a review in both Edit Profile and Privacy & Safety: existing Everyone posts can reach non-followers; followers-only posts and blocks are unchanged. Usernames are checked case-insensitively and the sign-in email is read-only. Email and phone are not sent in other members’ profiles. Enabling Private Account limits posts to existing followers and pauses new follows; it does not hide the directory listing. Deleting an account requires typing `DELETE`, removes its posts, saves, follows, recovery tokens and sessions, and retires its profile ID and founder designation.

## Social pages

- **Messages** (`/messages`, `/messages/<member-id>`): choose a real member to start a conversation. Search the inbox by name or message, send text or a compressed photo, and see unread counts and read receipts. Open threads refresh every 4.5 seconds while visible. Earlier messages can be loaded in batches. Only the sender and recipient can fetch a message photo. Messages are stored in SQLite, not end-to-end encrypted; no simulated support accounts, online status, or voice/video calls.
- **Explore** (`/search?q=…`): People, Posts, and Reels filters search member names, handles, captions and post locations. Results respect current post visibility. No placeholder posts or view counts are inserted.
- **Reels** (`/reels`): real video posts, with play/pause, seeking, volume, fullscreen (browser permitting), unique member views, likes, comments, shares and saves. Publish a video in Create Post to appear here. The share count counts distinct members who copied or shared a link through the share control, not recipients.
- **Post detail** (`/post/<id>`): open from the feed, search results, a profile, notification or reel. Read comments, reply, like, or share the stable link; the link does not grant access. Text-only posts display their text instead of a stock photograph.
- **Notifications** (`/notifications`): follows, post likes, comments, replies and visible `@username` mentions. Filter activity, follow back, open the referenced item or mark all read. Profile visits and individual saves are not disclosed.
- Motion uses short entry/interaction transitions and respects the device’s reduced-motion setting. `npm run test:ui` exercises these screens with isolated accounts, including a third-party privacy check and a real short WebM generated at test time. Optional `SOCIAL_SCREENSHOTS` names a directory for review images.

## Linkbacks

Open **Post options → Start a Linkback** on a post or reel, optionally write an opening message, then choose people to invite. **Messages → Linkbacks** lists your recent groups and invitations separately from direct messages. **Your Linkbacks** on a post lists only your own groups about it. A post author has no special access to other people’s conversations. Copying a group link does not invite anyone.

Invitees must accept before seeing the conversation, participant list, or pinned decision. Select a message to preview and pin it above the conversation. Details lets the admin invite or remove members and resend or cancel pending invitations. If the admin leaves, the longest-standing remaining member becomes admin. Leaving also cancels your outstanding invitations; groups with no remaining members close.

Original post previews use the current viewer’s post permissions rather than storing a copy. A deleted or newly private post is replaced by an unavailable state while group messages and decisions remain. Blocking a member leaves groups you share with them. Invitations respect blocks and the recipient’s messaging preferences. Linkbacks are private to their participants, **not end-to-end encrypted**.

The inbox shows the latest 100 groups/invitations; search matches the visible post, latest message, pinned decision, inviter, or group number. Threads load in batches of 60 messages and refresh while visible. Each group supports up to 30 participants including outstanding invitations.

## Member settings and stories

Open **Settings** from navigation to search account, privacy, notification and appearance controls. Notification preferences affect new in-app activity, not historical notices; push and email notifications are not delivered. Appearance includes system/light/dark mode, accent color, reduced motion and separate video and reel autoplay preferences. All screens use the same surface and action colors from `public/theme.css`; saved appearance changes carry across navigation and open tabs. Media backdrops remain neutral for legibility.

Profile counts open searchable follower/following lists. **Saved** shows your private bookmarks and collections. Use **Report or Block** on another member’s profile or post to report, block, mute or unfollow. Reports are stored for operator review; there is no automated moderation decision or moderator dashboard. Blocked and muted accounts can be managed in Privacy & Safety.

**Create Story** supports a photo, video or provided background, plus caption, audience and reply controls. Stories expire after 24 hours. Replies and quick reactions go to the author’s inbox and require messaging permission.

**Account & Security** lists active sessions, lets password users change their password, and offers authenticator-based two-factor sign-in with single-use recovery codes. To enable enrollment, provision `AFTERLINK_2FA_KEY` as a stable secret (32 random bytes encoded as base64; generate with `openssl rand -base64 32`). Back it up separately from the database. Do not regenerate it on restart or commit it. Without it, new enrollment is unavailable. Google-only accounts use their provider for sign-in security.

## Server configuration

- `PORT` — default `3000`.
- `DB_FILE` — SQLite filename; in production use an absolute path on a persistent volume, or any writable path when `DATABASE_URL` provides durability.
- `DATABASE_URL` — Postgres (e.g. Supabase) connection string for snapshot persistence. Set it privately in the host's environment; never commit it. Optional companions: `DATABASE_SSL=disable` for a local non-TLS Postgres, `DATABASE_CA_CERT` to verify the server certificate, `DB_SYNC_INTERVAL_MS` (default `15000`), `DB_SNAPSHOT_MAX_MB` (default `64`).
- `TRUST_PROXY_HOPS` — only set to a known/trusted reverse-proxy hop count for client IP rate limiting.
- **Google sign-in:** Create a **Web application** OAuth client in Google Auth Platform → Clients. Configure Branding and Audience first; if the external app is in Testing, add the Google accounts that will test it. Register the exact **Authorized redirect URI** `https://YOUR-SITE/auth/google/callback` (no trailing slash). Use the same hostname visitors use for sign-in so the state cookie accompanies the callback.
- Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` privately in the web service environment. On Render’s default hostname the app derives the callback from `RENDER_EXTERNAL_URL`. For a custom domain or another host set `GOOGLE_REDIRECT_URI` explicitly to the registered URL. For local development only, `http://localhost:3000/auth/google/callback` is supported. Never commit the secret or paste it into chat.
- **Verify activation:** after restarting the service with those settings, visit `/api/providers` (expect `{"google":true}`), then try **Continue with Google** in a private window. The flag only confirms local configuration; only a completed sign-in confirms the credentials and Google consent settings. A verified Google identity creates or reopens its AfterLink account. Existing password accounts with the same email are not automatically linked. No schema migration is required. Before redeploying, verify the existing database is on persistent storage; do not change `DB_FILE` to enable OAuth.
- **Rehearse without credentials:** With Playwright Chromium installed, `npm run test:google-ui` uses a static page and a simulated Google return to check retry, cancellation, and returning to the sign-up form. It does not open SQLite or verify a production login.

## Password recovery

**Forgot password?** opens the email form without reloading the illustration. To deliver reset emails, set `RESEND_API_KEY` (server secret), `RESET_FROM_EMAIL` (a sender verified with Resend), and `RESET_PUBLIC_ORIGIN` (the public HTTPS origin of this deployment) on the web service. Never commit the API key. With these settings absent, the form explicitly reports that no link was sent. Check the provider’s delivery logs when enabling email and disable provider click tracking for reset links.

Links expire in 15 minutes, contain a random single-use token in the URL fragment, and are replaced on resend after a one-minute cooldown. Only token hashes are stored. Requests return the same acknowledgment for eligible, unknown, and Google-only addresses. The reset form requires matching passwords of 12–128 characters with at least one uppercase letter and one number. A successful password reset revokes existing sessions; the user signs in again.

## Direct messages and calls

In a one-to-one chat, **+** offers photos, animated GIF files and voice notes. You can also paste an image into the message field or drop one image into the open chat. The preview shows the processed file size before sending and preserves your caption. Photos and GIFs default to **Keep in chat**. **View once** requires an explicit open by the recipient: the server consumes the payload before returning it, even if delivery is interrupted. Captions stay in chat. This is not screenshot prevention or a promise of erasure from backups. Voice notes can be paused, previewed, discarded and played back. During capture a local microphone indicator shows sound or quiet; reduced motion keeps the text without animation. A warning appears in the last 15 seconds of the two-minute recording limit (paused time does not count). The limit opens a preview, never an automatic send. Browsers that support leave prompts can warn before discarding a recording or unsent attachment; this is not draft storage. Each sent voice note has its own playback speed control. Direct and group message fields show the remaining character budget near the 1,000-character limit. Uploads are limited to 4 MiB after processing and 64 MiB stored per sender; existing chat photos remain readable.

Audio and video calls use WebRTC between browsers, not recorded messages. Both members should have Messages open and allow the requested device access. Use HTTPS (or localhost for development); an embedded preview also needs the host to permit microphone/camera access. The caller sees **Call declined** only if the recipient explicitly declines a ringing invitation, and **No answer** when the 45-second ringing window expires. Other endings stay neutral. These outcomes are short-lived in memory, not a call history. If the media connection fails or times out while connecting, AfterLink releases capture and offers **Redial with audio/video** or **Dismiss**. It never sends a new invitation automatically. Redial keeps a muted mic muted and uses audio only if your camera was off. Direct connections can expose network addresses to the other participant. The single web process holds invitation and signaling state in memory only: restarting it ends calls, not chat history. A browser that is closed does not receive push calls.

For calls across mobile networks, NATs and firewalls, provision a reachable TURN service. Set `CALL_TURN_URL` (for example `turns:turn.example.org:443?transport=tcp`) and `CALL_TURN_SECRET` (the TURN server's shared REST authentication secret) on the web service. Clients receive short-lived usernames and credentials, not the shared secret. Optionally set `CALL_STUN_URL` to your STUN service. Without ICE server configuration only directly reachable peers can connect. Before launch, use the [mobile call release checklist](docs/mobile-call-checklist.md) to verify direct and relayed calls on separate networks. During a connected call, **My call settings → Check connection** takes a short, local sample of the selected path’s round-trip time and incoming audio packet loss. Good/Fair/Poor is an estimate for that moment, not a speed test or a guarantee of audio quality. When available, the path is labeled Direct or TURN relay. No stats are sent to AfterLink.

Red **Messages** and **Notifications** badges show unread counts. The Messages total includes direct chats, group/Linkback messages and pending invitations; opening a conversation clears its delivered messages. **Typing…** appears in direct chat and watch chat while the other member types. Only short-lived presence is shared, not drafts. Either person can disable it in Settings → Privacy & Safety.

Use **Messages → Unread** to show only direct chats with unread messages, or open `/messages?view=unread`. On reopening a conversation, the first unread message is marked; if it predates the loaded page, the marker points to earlier history. Select a contact’s name → **Pin chat to inbox** to keep that conversation at the top of your own list. This is separate from pinning a message for both participants.

In direct chat, closing **Message actions** returns keyboard focus to the same message, even after a live update. **Reply** moves focus to the composer instead. A polite screen-reader announcement names the sender and counts new incoming messages without reading message text, previously loaded history, or reactions.

Use the magnifying glass in a direct chat to search its full message text and captions. Open **Filters** to choose a sender, a starting date, or an inclusive ending date in your local time zone. You can leave the search box blank when a filter is set. Open a match, a reply’s quotation, or the pinned banner to see up to three earlier and three later messages, without moving the live chat or opening attachments.

In a direct chat, press **Enter** to send or **Shift+Enter** for a new line. Reading earlier messages keeps your place: **New messages ↓** jumps to the latest, and the read badge clears when you reach the bottom of the visible thread.

Messages appear locally as **Sending…** until acknowledged. Retries reuse a client message ID. While the chat remains open, a transient send failure gets up to two automatic retries after connectivity returns or a successful thread refresh. Dismiss cancels a queued retry; drafts awaiting confirmation are not stored across reloads. Authenticated server-sent wake-ups refresh open chats and deliver WebRTC signaling changes without a polling delay. Allow streaming (disable proxy buffering) on `/api/feed/live`. Periodic reconciliation works if the stream is unavailable. Groups show when live updates are reconnecting and fetch the current permitted view on reconnect. A burst of events during an active group refresh schedules one follow-up rather than overlapping requests. `npm run test:group-live` rehearses this with two isolated Chromium sessions and a real, interrupted event stream backed by an in-memory fixture. ICE candidates are sent as they arrive; live audio/video still travels through WebRTC, not through the web server. Network distance, packet loss, TURN placement and device encoding capacity all affect latency.

**Message actions → Copy text** copies a message or caption. If clipboard access is blocked, the app selects the text for manual copying. The message menu also supports replies, a shared conversation pin, emoji reactions, forwarding kept messages and unsending your own messages. Unsend removes the original attachment and body for both members, not copies already saved or forwarded. Emoji data (including skin tones, flags and joined sequences) is derived from `emojibase-data` 18.0.0, see `public/assets/emoji-LICENSE.txt`; the browser fetches it only when the picker opens. Choose **Recently used** to search your last 24 distinct picks from messages and reactions. Recents stay in this browser, are separated by signed-in account, and can be removed with **Clear recent emojis**. In open DM, group, and Linkback threads, the first keyboard link jumps to the message field. In forced-colors mode, unread badges use system colors and selected filter chips have a double underline. Notes on Home and Messages are visible to followers and stay until edited or removed.

**In-call recording is opt-in.** After connecting, choose **Request recording**, review what will be captured, then **Ask for consent**. The recipient sees the same scope before allowing: both microphones and optional screen pixels, not shared-tab or system sound. Only after the other member allows it can you start an audio recording or choose a screen/tab in the browser's screen picker. Both participants see the recording status and either may stop it. The browser mixes the two call voices locally, without playing them through a second output or adding another video track to the call. The file downloads to the recorder's device; no recording bytes are uploaded. Both people see elapsed recording time. The recorder sees a warning with one minute remaining or at 90% of the approximately 64 MiB size limit. Recording stops after 10 minutes or when the size limit is reached. If the automatic download is missed, **Download recording again** offers the same file for five minutes, even after hanging up on the same Messages page. Only the latest file is kept in page memory; dismissing the link or leaving the page clears it. Browser support for MediaRecorder, Web Audio, and (for screen recording) `getDisplayMedia` is required. Use a top-level HTTPS page if an embedded host doesn't grant capture permissions.

Check **Start with mic muted** on an incoming call to join without transmitting microphone audio until you unmute. The minimized call explicitly shows **Mic on** or **Mic muted**.

**Answer with mic only** lets you take an incoming video call without granting camera access. You can still see the caller and turn on your own camera later. If camera capture fails, the invitation stays open for a mic-only answer until the caller hangs up or it expires.

**Switch to video** turns on your own camera during an audio call. The other member can choose **Camera on**; their camera does not start automatically. **Switch to audio** turns both cameras off without ending the call, screen share or recording. The bottom-right self-view fits the entire camera frame.

**Call size:** Choose Small, Medium (default), or Large in an audio or video call. Minimize (or Escape during a call) docks the call on the current Messages page so you can type without hanging up. While minimized, use **Dock position** to move the call to any corner without changing your mic state or message draft. The chosen corner stays in effect for this call; a new call starts at bottom right. Long contact names are shortened visually on narrow screens but remain available to assistive technology. **Restore call** returns it to your last expanded size. Resizing affects only your own view.

**My call settings** lets you adjust your partner’s playback volume independently of shared-tab audio, or hide your self-preview while your camera stays on. On supported browsers, **Choose partner voice output** routes your partner to a speaker or headset without redialing. **Choose shared tab output** separately routes the tab you are watching. Each starts on the system default, and **Use system default** restores it. Devices are requested only when you choose an output; their identifiers are not stored or sent to AfterLink. If browser output selection is unavailable, use the system sound settings. The tab volume control appears when you are watching someone else’s tab; your own shared preview stays muted to avoid echoes. These controls reset with each call and do not change outgoing tracks or the call-voice recording mix. On browsers that reserve volume for hardware buttons, the controls offer local mute instead.

**Watch together** is available after a one-to-one audio or video call connects. Either participant can open a website in a separate tab, then select **Watch together → Share a tab** and choose it in the browser’s permission picker. Only one person presents at a time; they control navigation/playback. Enabled cameras, microphone audio and the existing direct chat stay available. Where supported, float the other person's camera over the website using picture-in-picture. Stop sharing (or end browser capture) without ending the call. No site is embedded or proxied through AfterLink, and shared pages are not stored. Tab sound depends on the browser and the presenter's audio-sharing selection. The presenter sees whether an audio track was captured and can pause or resume just that track; the conversation microphone stays independent. If autoplay is blocked, the viewer can use **Play shared tab**. Either participant can choose **Expand shared tab** to hide chat on their own screen. **New messages** appears when their partner sends a message while chat is hidden. **Show conversation** returns keyboard focus to the message field without clearing the draft. Some browsers cannot present tabs, and protected/DRM video may not be capturable. Watch together does not bypass those restrictions. Camera resolution/bitrate is reduced during presentation to leave bandwidth for speech and the shared content; this does not eliminate network latency.

**Messages → Groups → Create group** starts a named private group chat without a post. Invitees must accept before they can read the chat or send messages. Admins can change the group name and optional 200-character topic under **Details → Edit group**. The name appears on the invitation; the topic stays private until the invitee joins. Both the Groups and Linkbacks inboxes have **Unread chats** (joined conversations with unread messages) and **Invitations** filters. In **Details**, search joined members and pending invitees by name. Live roster updates preserve the filter, text selection, and focused action for the same member. If that action disappears, focus returns to search rather than another member’s controls. Stale confirmation dialogs still close when membership changes. Both count toward the 30 places; the picker shows remaining capacity as you select people. **Make admin → Confirm transfer** hands off the role to a joined member without leaving. **Leave group** lets you review the successor or group closure and the names of invitees whose invitations would be cancelled before you confirm. Post-based Linkbacks remain separate. In a direct chat, select the member's name to save a private nickname; this changes your inbox/search and call labels, not the other member's profile or anyone else's view.
